# 常见错误与修复指南

> 本文档记录项目中已知的 runtime 错误及其根因和修复方案。
> Agent 在集成新模块或创建 YAML 时，应先阅读本文档，避免重复踩坑。

---

## 一、AMP 混合精度 dtype 不匹配（最高频）

### 1.1 错误表现

```
RuntimeError: Input type (torch.cuda.FloatTensor) and weight type (torch.cuda.HalfTensor) should be the same
```

### 1.2 根因

`ultralytics/engine/validator.py` 第 119 行，在每轮训练后验证时，将整个模型强制转为 float16：

```python
model = model.half() if self.args.half else model.float()
```

此时模型所有参数和缓冲区变为 `torch.float16`（HalfTensor）。如果模块内部的某些操作（FFT、DCT、Sobel 等）产生 `float32`（FloatTensor）输出，后续的 `Conv2d` 层就会因为输入 float32 而权重 float16 而崩溃。

训练阶段使用 `autocast` 上下文管理器，PyTorch 会自动处理 dtype 转换，**不会崩溃**。问题只在验证阶段的 `.half()` 转换。

### 1.3 已知触发模块与修复模式

| 模块 | 触发操作 | 修复模式 |
|------|---------|---------|
| `FDConv` | `torch.fft.fft2()` 输出 float32 | 前 `.float()`，后 `.to(dtype)` |
| `EBlock` (DarkIR) | `torch.fft.fft2()` 在 half 精度下触发 cuFFT 限制 | 前 `.float()`，后 `.to(dtype)` |
| `FreqSpatial` (SFEM) | `torch.fft.rfft2()` / `irfft2()` 触发 cuFFT 限制 | 前 `.float()`，中间 Conv `.to(dtype)`，后 `.to(dtype)` |
| `FADC` | `F.conv2d()` + Sobel buffer 产生 float32 梯度 | 梯度计算统一 float32，后 `.to(x.dtype)` |
| `vHeat` | DCT 矩阵乘法 + `torch.exp()` 精度 | DCT/IDCT 全程 float32，投影前 `.to(dtype)` |
| `vHeat_Fusion` | DCT 缓存 dtype 与 `torch.exp` 类型提升后不一致导致 KeyError | DCT 矩阵始终缓存 float32，频域运算全程 float32，投影前 `.to(dtype)` |
| `SOCA` | `Covpool`/`Sqrtm` 自定义 Function 内部 `bmm`+`eye` 产生 float32 | 协方差池化输入 `.float()`，结果 `.to(dtype)` |
| `ACmix` | `position()` 用 `torch.linspace` 产生 float32 | `.to(x.dtype)` |

### 1.4 通用修复模板

**原则**：频域/梯度操作统一在 float32 中完成，最后 `.to(dtype)` 恢复原始精度。

```python
def forward(self, x):
    dtype = x.dtype  # 保存原始 dtype

    # 需要 float32 精度的操作
    x_f32 = x.float()
    # ... FFT / DCT / Sobel 等操作 ...
    result = ...  # float32

    # 恢复原始 dtype，送入后续 Conv/BatchNorm
    out = result.to(dtype)
    out = self.conv(out)
    return out
```

### 1.5 具体修复示例

#### FDConv（频域解耦卷积）

```python
def forward(self, x):
    dtype = x.dtype
    x_f32 = x.float()                    # 升精度
    x_fft = torch.fft.fft2(x_f32, ...)   # FFT 在 float32 中
    # ... 频带调制 ...
    x_mod = torch.fft.ifft2(...).real.to(dtype)  # IFFT 后恢复 dtype
    out = self.conv(x_mod)                # Conv 收到正确 dtype
    return out
```

#### ACmix（混合注意力+卷积）

```python
# 修复前
pe = self.conv_p(position(h, w, x.is_cuda))

# 修复后
pe = self.conv_p(position(h, w, x.is_cuda).to(x.dtype))
```

### 1.6 哪些操作容易触发此问题

- `torch.fft.fft2` / `torch.fft.ifft2` — 傅里叶变换（**特别注意**：cuFFT half precision 模式仅支持 2 的幂次维度，如 64/128/256/512，非 2 的幂如 160/320 会直接报错）
- `torch.fft.rfft2` / `torch.fft.irfft2` — 实数傅里叶变换（同上限制）
- `torch.dct` / `torch.idct` — 离散余弦变换（如果使用 scipy/torch-dct）
- `F.conv2d` 手动调用（非 `nn.Conv2d`）— 特别是 kernel 是 `register_buffer` 时
- `torch.linspace` / `torch.arange` 创建的张量 — 始终 float32
- `torch.exp` / `torch.log` 等超越函数 — 在 float16 下可能精度不足

### 1.6.1 cuFFT half precision 维度限制（常见坑）

当 AMP autocast 将输入转为 float16 后，`torch.fft.fft2` 会调用 cuFFT 的 half precision 路径。该路径**仅支持信号维度为 2 的幂次**（64, 128, 256, 512, ...）。YOLO 的多尺度特征图常见尺寸如 160×160、320×320、80×80 中：

- 64×64 ✅、128×128 ✅、256×256 ✅、512×512 ✅
- **80×80 ❌、160×160 ❌、320×320 ❌**、40×40 ❌、20×20 ❌

因此**几乎所有 YOLO 多尺度特征图都会触发此问题**。唯一的通用解法是 `.float()` 升精度后再做 FFT。

### 1.7 哪些操作不会触发此问题

- `nn.Conv2d` / `nn.Linear` — PyTorch 自动处理 dtype
- `nn.BatchNorm2d` — 自动匹配输入 dtype
- `nn.ReLU` / `nn.SiLU` / `nn.GELU` — dtype 无关
- `torch.matmul` / `torch.einsum` — 纯矩阵运算，dtype 由输入决定
- `F.relu` / `F.silu` — dtype 无关

## 二、repeat_modules 遗漏导致通道不匹配

### 2.1 错误表现

模型构建不报错，但训练时通道维度不匹配：
```
RuntimeError: Given groups=1, weight of size [256, 256, 7, 7], expected input[2, 512, 80, 80] to have 256 channels, but got 512 channels instead
```

### 2.2 根因

`parse_model` 中，YAML 的 `n` 参数（重复次数）有两种处理方式：

```python
# tasks.py 第 1226-1228 行
if m in repeat_modules:
    args.insert(2, n)  # 将 n 作为模块的第 3 个参数传入
    n = 1              # 外部只创建 1 个实例，内部自己重复
```

- **在 `repeat_modules` 中**（如 C3k2, C2PSA）：`n` 作为参数传入模块，模块内部处理堆叠
- **不在 `repeat_modules` 中**（如 StarBlock, vHeat）：`n` 控制外部 `nn.Sequential` 的实例数

当 `n=2` 且模块不在 `repeat_modules` 中时：
```python
m_ = nn.Sequential(StarBlock(c1, c2), StarBlock(c1, c2))
```
两个实例收到相同的 `c1`，但第二个实例的输入是第一个的输出（`c2` 通道），导致通道不匹配。

### 2.3 已知受影响模块

| 模块 | 是否在 repeat_modules | YAML 中 n=2 时的行为 |
|------|:---:|------|
| C3k2 | ✅ | 正确：内部创建 2 个 bottleneck |
| C2PSA | ✅ | 正确：内部创建 2 个 PSA block |
| Att_SFEM | ✅ | 正确：继承 C2f，内部处理 n |
| Att_IRAFAB | ✅ | 正确：继承 C3k2，内部处理 n |
| **StarBlock** | ❌ | **错误**：Sequential 两个实例通道不匹配 |
| **vHeat** | ❌ | 不报错但语义错误：只创建 1 个实例 |
| **TOST** | ❌ | 不报错但语义错误：只创建 1 个实例 |

### 2.4 修复方式

**方式 A**：将 YAML 中 `n=2` 改为 `n=1`（推荐，适用于不支持堆叠的模块）

```yaml
# 修复前
- [-1, 2, StarBlock, [512]]

# 修复后
- [-1, 1, StarBlock, [512]]
```

**方式 B**：将模块加入 `repeat_modules` 并修改 `__init__` 接受 `n` 参数

```python
# 在 StarBlock.__init__ 中添加 n 参数
def __init__(self, c1, c2, n=1, mlp_ratio=3.0, drop_path=0.0):
    super().__init__()
    self.blocks = nn.Sequential(*[StarBlockCore(c1 if i == 0 else c2, c2, mlp_ratio, drop_path) for i in range(n)])
```

### 2.5 排查清单

创建 YAML 时，如果模块使用了 `n > 1`，必须确认：
1. 模块是否在 `tasks.py` 的 `repeat_modules` 集合中
2. 模块的 `__init__` 是否接受 `n` 作为第 3 个参数
3. 如果两者都不满足，将 `n` 改为 `1`

## 三、BatchNorm + 空间 1×1 + bs=1 崩溃

### 3.1 错误表现

```
ValueError: Expected more than 1 value per channel when training, got input size [1, 256, 1, 1]
```

### 3.2 根因

YOLO 初始化时用 `torch.zeros(1, ch, 32, 32)` 做 stride 推断。P5 层特征图空间尺寸为 1×1，`BatchNorm2d` 在 `training=True` 时要求每个通道至少有 2 个值。

### 3.3 修复

所有门控/归一化路径统一用 `nn.GroupNorm(1, channels)` 替代 `nn.BatchNorm2d`。

```python
# 修复前
self.gate = nn.Sequential(
    nn.Conv2d(c, c, 1),
    nn.BatchNorm2d(c),   # P5 空间 1×1 时崩溃
    nn.Sigmoid(),
)

# 修复后
self.gate = nn.Sequential(
    nn.Conv2d(c, c, 1),
    nn.GroupNorm(1, c),  # GroupNorm 不依赖空间尺寸
    nn.Sigmoid(),
)
```

## 四、EMA 与 register_buffer 不兼容

### 4.1 错误表现

训练报错或 checkpoint 加载时 key 不匹配。

### 4.2 根因

EMA 保存模型状态字典时，`register_buffer` 动态注册的缓存会导致 key 不匹配。

### 4.3 修复

用普通 Python dict 缓存，不使用 `register_buffer`：

```python
# 修复前
self.register_buffer("_cache", torch.zeros(...))

# 修复后
self._cache = {}  # 普通 dict，兼容 EMA
```

参考实现：`vHeat_Fusion` 的 `_dct_cache`。

## 五、DecoupledHead 检测头使用注意事项

### 5.1 EMA 必须关闭

DecoupledHead 与 EMA 不兼容。训练时必须传 `--ema false`：

```bash
python train_AddModules.py --model_yaml path/to/yaml --ema false
```

训练脚本会自动用 `_DummyEMA` 占位对象替代真实 EMA。

### 5.2 NMS 输出格式差异

DecoupledHead 在 eval 模式下输出 **已解码的边界框** `(cx, cy, w, h)`，而标准 Detect 输出 **DFL 原始 logits**。`non_max_suppression` 会尝试对前 4 个通道做 `xywh2xyxy` 转换，对 DecoupledHead 的已解码坐标会产生错误结果（静默失败，mAP 为 0）。

**解决方案**：如果需要在训练后单独验证 DecoupledHead 模型，需要确保 postprocess 适配其输出格式。

## 六、timm 使用规范

### 6.1 timm 是项目依赖，可以直接使用

timm 已安装在训练环境中，新模块可以直接 `import timm` 或 `from timm.layers import ...`，无需改造为纯 PyTorch。

### 6.2 导入路径

新版 timm 中 `timm.models.layers` 已废弃，应改用 `timm.layers`：

```python
# ✅ 正确
from timm.layers import DropPath, make_divisible

# ⚠️ 能用但有 FutureWarning
from timm.models.layers import DropPath
```

### 6.3 timm 1.0.26 已知 bug

- `timm.layers.GatherExcite`: 内部 `ConvMlp.__init__()` 的 `act_layer` 参数冲突，无法直接使用。已用纯 PyTorch 重写 `Att_GatherExcite`。

## 七、自检清单（创建新模块/YAML 时）

- [ ] 模块是否使用 FFT/DCT/Sobel 等频域/梯度操作？→ 加 `.float()` + `.to(dtype)` 保护
- [ ] YAML 中是否有 `n > 1` 的模块？→ 确认模块在 `repeat_modules` 中
- [ ] 模块内部是否使用 `BatchNorm`？→ P5 空间 1×1 时是否安全？考虑用 `GroupNorm`
- [ ] 是否使用了 `register_buffer` 动态缓存？→ 改用普通 dict，兼容 EMA
- [ ] 检测头是否为 DecoupledHead/ATAH？→ 训练时需 `--ema false`
- [ ] 是否依赖 `timm.models.layers`？→ 改为 `timm.layers`
