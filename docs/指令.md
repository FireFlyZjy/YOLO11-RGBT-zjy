## 二、全流程 6 步操作

### 步骤1: 扫描筛选外部源码

**1a. 定位源码**: 在外部仓库中寻找 `.py` 文件，名字通常包含模块关键词（attention/conv/fusion/block/head）。

**1b. 读取核心**: 至少读取类的 `__init__` 和 `forward` 方法，理解：
- 输入输出维度关系
- 是否有外部依赖（mmcv / timm / CUDA）
- 参数量量级

**1c. 对照已有模块判断**:

| 判断 | 决定 | 示例 |
|------|------|------|
| 需要 CUDA 扩展 / mmcv-full | ❌ 跳过或改写 | DCNv3 → 需编译 CUDA |
| 完整 backbone/neck 替换，非即插即用 | ❌ 跳过 | Swin-T, GFPN |
| 源码有 bug / 不可运行 | ❌ 跳过 | SPConv → 未定义变量 |
| 机制与已有模块重叠 | ⚠️ 纳入+标注 | 仍加入, 但标注 `[重叠: 与XXX功能类似]` |
| 纯 PyTorch，<1M 参数 | ✅ 纳入 | CoordConv, StarBlock |
| 纯 PyTorch，>1M 但有明确价值 | ⚠️ 需评估 | ICAFusion (16.6M) |
| 针对 IR/频域/跨模态融合有专门设计 | ✅ 优先 | EBlock, FDConv, vHeat |

**1d. 输出筛选表**（追加到改进位置.md）:

```markdown
| 模块 | 决定 | 原因 |
|------|------|------|
| XXX | ✅ 纳入 | 机制与现有模块互补 |
| YYY | ⚠️ 纳入[重叠] | 与已有 ZZZ 功能类似, 但实现机制不同, 保留供消融对比 |
| ZZZ | ❌ 跳过 | 需要 CUDA 扩展, 部署不友好 |
```

### 步骤2: 实现模块 .py 文件

**2a. 选择子目录**: 按功能放入 `ultralytics/nn/ExtraModules/{子目录}/`：

| 子目录 | 存放内容 | 示例 |
|--------|---------|------|
| `attention/` | 注意力机制（通道/空间/自注意力） | CBAM, CoordAtt, AIFI |
| `conv/` | 卷积变体 | PConv, CoordConv, StarBlock |
| `fusion/` | 双模态融合模块（from为列表） | CIFusion, AFF, ICAFusion |
| `head/` | 检测头（替换Detect） | ATAH, DecoupledHead |
| `frequency/` | 频域模块（FFT/DCT） | FDConv, vHeat, TOST |
| `mamba/` | SSM状态空间模型 | EfficientViM, WTE_Mamba |
| `dynamic/` | 动态/自适应卷积 | DynamicConv |
| `context/` | 全局上下文聚合 | EVC, ContextAgg |
| `neck/` | 颈部模块（上采样/融合） | CARAFE, ASF |
| `loss/` | 独立损失/后处理工具 | NWDLoss, SoftNMS |

**2b. 创建模块文件**: 文件名 = 模块名.py

**2c. 类定义规则**: 3 种模板（单输入/多输入/检测头）见 → [代码模板](reference/code_templates.md)
核心要点: c1/c2 前两参数 · 1×1 投影处理 c1≠c2 · forward 处理 list/tuple 输入 · 检测头需 dynamic/export/strides 等类属性

**2d. 硬约束**:
- 禁止依赖 mmcv / mmengine / mamba-ssm（只能用 PyTorch + torchvision + timm）
- c1/c2 必须作为前两个位置参数
- 1x1 投影必须在 `__init__` 中处理 c1 != c2 的情况
- 文件名 = 主类名.py

**2e. 创建 `__init__.py`**: 如果子目录是新的，创建 `__init__.py`，内容为 `from .模块名 import *`

### 步骤3: 注册到 YOLO 框架

**3a. `__init__.py` 追加导入**:
```
文件: ultralytics/nn/ExtraModules/__init__.py
操作: 在 "YOLO 包装器" 行之前追加
格式: # 日期 说明
      from .子目录.模块名 import *
```

**3b. `tasks.py` 注册 — 3种情况**（精确插入位置见 → [代码模板](reference/code_templates.md)）:

**情况1: 普通单输入模块**（替换Conv/C3k2/SPPF等，from是单个layer）
- 追加到 `base_modules` 集合内（约行1080）
- 需 n 参数时追加到 `repeat_modules`（约行1104）

**情况2: 多输入模块**（from是列表，如融合模块）
- 追加到 `base_modules`（同上）
- 追加到 `parse_model` 多输入分支的 `if m in (...)` 括号内（约行1121）

**情况3: 检测头模块**（替换Detect）
- 追加到 `parse_model` 检测头分支的 `elif m in (...)` 括号内（约行1125）
- 追加到 `isinstance` 检查（约行296、行362）

**3c. 不需要注册的模块类型**:
- `loss/` 下的独立工具（NWDLoss, SoftNMS）— 它们不通过YAML使用
- `tools/` 下的脚本 — 独立运行

### 步骤4: 创建 YAML 配置文件

**4a. 核心原则**: **原位替换** — 不改层号，只换模块名。除非必须插入新层（此时需层号位移对照表）。

**4b. YAML 目录规则**:
```
ultralytics/cfg/models/26-RGBT/{YYYY-MM-DD}/{分类}/{文件名}.yaml

分类: conv / dynamic / context / neck / head / frequency / mamba / fusion / attention
文件名: yolo26-RGBT-midfusion-{模块名}.yaml
```

> **重要**: `{YYYY-MM-DD}` **必须使用创建当天的实际日期**（如今天=`datetime.now().strftime('%Y-%m-%d')`），
> 创建目录前先用 `powershell -Command "Get-Date -Format 'yyyy-MM-dd'"` 确认当天日期，**不可使用其他日期**。

**4c. 创建流程**:

> **⚠️ 第一步必须是确认日期**: 执行 `powershell -Command "Get-Date -Format 'yyyy-MM-dd'"`
> 然后以该日期作为 `{YYYY-MM-DD}` 创建目录，**不可使用其他日期，不可凭记忆写日期**。

1. 复制基线模板 `yolo26-RGBT-midfusion.yaml` 全部内容
2. 找到目标层 → 只改模块名和 args，不改 layer 编号
3. 每行加层号注释 `# N-说明`
4. 头部写清楚：改了哪些层、什么变化

**5d. 训练冒烟测试**（必须，不可跳过）:

模块通过导入/YAML验证后，必须运行 2 epochs 训练冒烟测试，确认训练循环能完整跑通（前向+反向+保存）。
只有冒烟测试通过后，才能继续执行步骤6更新文档。

```bash
D:\Anaconda\envs\torch310\python.exe -c "
from ultralytics import YOLO
model = YOLO('ultralytics/cfg/models/26-RGBT/YYYY-MM-DD/分类/yolo26-RGBT-midfusion-模块名.yaml')
model.train(data='ultralytics/cfg/datasets/flir.yaml', epochs=2, batch=2, device='0', workers=0,
            use_simotm='RGBT', channels=4, close_mosaic=0)
"
```
预期输出：2个epoch完整跑通，保存 best.pt / last.pt，无报错。

**常见训练报错及修复**:
- `Sizes of tensors must match` → 检查模块在空间1x1 (P5) + bs=1时是否兼容，BN改GroupNorm
- `Expected more than 1 value per channel` → BatchNorm在GAP后空间1x1时崩溃，改GroupNorm
- `register_buffer` 与 EMA 不兼容 → 改用普通 dict 缓存（参考 vHeat_Fusion）
- CUDA OOM → 减小 batch size 或 imgsz
- `module not found` → 检查 `__init__.py` 导入和 `tasks.py` 注册

### 步骤6: 更新文档

每次修改后必须同步更新以下 4 个文档（位于 `docs/`）：

**6a. 改进位置.md** — 追加 `## YYYY-MM-DD` 段，包含：
- 配置目录路径
- 文件修改对照表（配置文件 vs 模块 vs 改动）
- 具体改动行号（如 tasks.py 第1080行追加）
- 层号位移对照表（Backbone 和 Head 分开，**仅当有位移时**）
- 代码文件修改表
- 架构 ASCII 图（**仅当模块改变数据流时**）
- 筛选结果表（**仅当涉及筛选时**）

**6b. 创新点.md** — 追加 `## YYYY-MM-DD` 段，包含：
- 模块名称、来源论文、核心机制（2-3句）
- 参数量（vs 被替换模块）、改进动机
- 插入策略（替换哪个层、为什么选这个位置）
- 验证结果（实例化 + forward pass 是否通过）

**6c. 论文级创新点.md** — **仅当模块满足以下准入条件之一时**追加 `## YYYY-MM-DD` 段：

**准入条件**（满足任一）:
- mAP50 > 0.865（经训练验证，从 `runs/val_results.csv` 查询实测值）
- 创新性极高，提点潜力巨大（即使 mAP50 暂未达标，但机制原创性足以独立成文）

**创新特征**（准入后需具备至少一项）:
- 首次将某个机制应用于 RGB-T 跨模态融合（如频域融合、热传导融合）
- 提出了全新的网络结构或算子（非已有论文的即插即用）
- 开辟了新的融合范式（如 DCT 域融合、SSM 融合、小波域融合等）
- 解决了 RGB-T 检测领域的某个核心挑战（模态差异、噪声抑制、特征对齐、跨模态互补）
- 模块需要有**物理可解释性**或**数学理论支撑**（如热传导方程、信息论等）

**mAP50 标注要求**:
- 每个条目必须标注涉及模块的 mAP50 实测值（从 `runs/val_results.csv` 查询）
- 未训练的配置标注"待训练"

**架构图规则**:
- **仅当模块 mAP50 > 0.865 时**，才在条目中画架构设计图（ASCII 架构图，参考 vHeat_Fusion 条目风格）
- 未达标的模块不画架构图，仅文字描述

**论文级创新点.md 与 创新点.md 的区别**:
- 创新点.md: 记录**所有**模块改进（含已有论文的即插即用模块，如 CBAM、ECA 等）
- 论文级创新点.md: 仅记录**原创性设计**（首次提出的新机制/新架构，可独立成文）
- 论文级创新点内容需包含: 问题定义、核心创新机制详解、与现有方法对比、消融实验建议

**6d. 指令.md** — 更新模块清单表中的计数和条目，确保模块参数速查表同步。

**文档日期规则**:
- **YAML目录日期**: `{YYYY-MM-DD}` **必须使用创建当天的实际日期**（不可用其他日期）
- 同日多次改进 → 不加新日期头，直接在当日段追加
- 不同日改进 → 先加 `## YYYY-MM-DD` 再写内容

## 十、项目全景理解（给下一个 Agent）

> 本节是对整个项目的深度理解，读完即可达到与前任 Agent 相同的工作水平。

### 10.1 项目定位

这是一个**基于 YOLO 框架的 RGB-T (可见光+红外) 双模态目标检测研究项目**。
核心目标: 在 YOLO 架构上系统性地集成、对比、筛选各种即插即用模块（注意力/卷积/融合/频域/SSM等），
找到最优的双模态检测配置，最终产出一篇高质量论文。

### 10.1.1 实验本质与论文目标

**涨点是王道**: 所有实验的根本目的是提升 mAP50。模块设计、组合创新、消融对比的最终评价标准都是能否涨点。不涨点的设计没有价值，无论多么精巧。

**保留创新点**: 尽量保留 3 个或更多论文级创新点，方便后续发表论文。具体策略:
- 同一范式的改进（如非对称骨干）迭代演进，替换掉 mAP50 不足的旧方案
- 不同维度的创新（backbone / neck / fusion / head）并行积累
- mAP50 > 0.865 的模块优先保留；创新性极高的模块可破例保留（需标注 mAP50 并注明原因）
- 论文级创新点.md 的准入与架构图规则见第九节第 14 条

**论文产出导向**: 每个创新点都应具备独立成文的能力，包含: 问题定义、核心机制、与现有方法对比、消融实验设计。最终论文结构通常为 3-4 个主要贡献点。

### 10.2 关键架构概念

**双模态 Mid-Fusion 架构**:
```
输入 [B,4,H,W] (RGB 3ch + IR 1ch)
    |
    ├─ SilenceChannel [0,3] → RGB分支 (独立backbone)
    └─ SilenceChannel [3,4] → IR分支 (独立backbone)
         |
    P3: Concat [vis_P3, ir_P3] → 融合模块 → Neck
    P4: Concat [vis_P4, ir_P4] → 融合模块 → Neck
    P5: Concat [vis_P5, ir_P5] → 融合模块 → Neck
         |
    SPPF → C2PSA → FPN/PAN Neck → Detect
```

**层号体系**: backbone 共 21 层 (层0-20) + 3个融合层 (层21/22/23) + SPPF(24) + C2PSA(25)，
然后 head 从层26开始。替换融合层时**原位替换**，不改变层号。

**模块分类与放置规则**:
- `fusion/`: 双输入融合模块 (from为列表) — CIFusion, AFF, vHeat_Fusion, FCMMFusion 等
- `attention/`: 单输入注意力 (from为单层) — CBAM, ECA, CoordAtt 等，插在 Concat 之后
- `conv/`: 卷积变体 — 替换 Conv 或 C3k2
- `frequency/`: 频域模块 — FDConv, vHeat, TOST 等
- `head/`: 检测头 — 替换 Detect
- `neck/`: 颈部模块 — CARAFE, ASF 等
- `mamba/`: SSM 模块
- `dynamic/`: 动态卷积
- `context/`: 全局上下文
- `loss/`: 独立损失工具

### 10.3 模块接入的三个关键文件

**文件1: `ultralytics/nn/ExtraModules/__init__.py`**
作用: 模块的导入入口。所有新模块必须在这里 `from .子目录.模块名 import *`，
且必须放在 `# YOLO 包装器` 行之前。

**文件2: `ultralytics/nn/tasks.py`**
作用: 模块注册。有三个注册点:
- `base_modules` (约1080行): 所有模块都要加
- `parse_model` 多输入分支 (约1183行): 仅融合模块 (from为列表) 需要加
- `repeat_modules` (约1140行): 仅需要 n 参数的模块需要加

**文件3: YAML 配置文件**
作用: 定义模型结构。放在 `ultralytics/cfg/models/26-RGBT/{YYYY-MM-DD}/{分类}/` 下，
从基线 `ultralytics/cfg/models/26-RGBT/origin/yolo26-RGBT-midfusion.yaml` 复制后修改。

### 10.4 常见踩坑点

1. **BatchNorm + 空间1x1 + bs=1 崩溃**: YOLO 初始化时用 `torch.zeros(1, ch, 32, 32)` 做 stride 推断，
   P5 层空间为 1x1，BatchNorm2d 会报 "Expected more than 1 value per channel"。
   **解决方案**: 所有门控/归一化路径统一用 `nn.GroupNorm(1, channels)` 替代 `nn.BatchNorm2d`。

2. **EMA 不兼容 register_buffer**: EMA 保存模型状态字典时，register_buffer 的动态缓存会导致 key 不匹配。
   **解决方案**: 用普通 Python dict 缓存（参考 vHeat_Fusion 的 `_dct_cache`）。

3. **timm 版本兼容**: `timm.models.layers` 已废弃，应改用 `timm.layers`。
   当前代码中有 FutureWarning，不影响功能但需注意。

4. **YAML 层号引用**: neck 的 Concat 引用的是 backbone 层号，替换融合层后如果层号变了，
   必须同步更新所有引用。推荐原位替换避免此问题。

5. **c1 参数传递**: 多输入模块的 c1 会被 parse_model 自动转为 list `[ch[f] for x in f]`，
   所以 `__init__` 必须处理 `isinstance(c1, (list, tuple))` 的情况。
