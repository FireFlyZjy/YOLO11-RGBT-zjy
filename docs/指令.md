## 二、全流程 6 步操作

### 步骤1: 扫描筛选外部源码

**1a. 定位源码**: 在外部仓库中寻找 `.py` 文件，名字通常包含模块关键词（attention/conv/fusion/block/head）。

**1b. 读取核心**: 至少读取类的 `__init__` 和 `forward` 方法，理解：
- 输入输出维度关系
- 是否有外部依赖（mmcv / timm / CUDA）
- 参数量量级

**1c. 对照已有模块判断**:

| 判断 | 决定 | 示例 |
|------|------|------|
| 需要 CUDA 扩展 / mmcv-full | ❌ 跳过或改写 | DCNv3 → 需编译 CUDA |
| 完整 backbone/neck 替换，非即插即用 | ❌ 跳过 | Swin-T, GFPN |
| 源码有 bug / 不可运行 | ❌ 跳过 | SPConv → 未定义变量 |
| 机制与已有模块重叠 | ⚠️ 纳入+标注 | 仍加入, 但标注 `[重叠: 与XXX功能类似]` |
| 纯 PyTorch，<1M 参数 | ✅ 纳入 | CoordConv, StarBlock |
| 纯 PyTorch，>1M 但有明确价值 | ⚠️ 需评估 | ICAFusion (16.6M) |
| 针对 IR/频域/跨模态融合有专门设计 | ✅ 优先 | EBlock, FDConv, vHeat |

**1d. 输出筛选表**（追加到改进位置.md）:

```markdown
| 模块 | 决定 | 原因 |
|------|------|------|
| XXX | ✅ 纳入 | 机制与现有模块互补 |
| YYY | ⚠️ 纳入[重叠] | 与已有 ZZZ 功能类似, 但实现机制不同, 保留供消融对比 |
| ZZZ | ❌ 跳过 | 需要 CUDA 扩展, 部署不友好 |
```

### 步骤2: 实现模块 .py 文件

**2a. 选择子目录**: 按功能放入 `ultralytics/nn/ExtraModules/{子目录}/`：

| 子目录 | 存放内容 | 示例 |
|--------|---------|------|
| `attention/` | 注意力机制（通道/空间/自注意力） | CBAM, CoordAtt, AIFI |
| `conv/` | 卷积变体 | PConv, CoordConv, StarBlock |
| `fusion/` | 双模态融合模块（from为列表） | CIFusion, AFF, ICAFusion |
| `head/` | 检测头（替换Detect） | ATAH, DecoupledHead |
| `frequency/` | 频域模块（FFT/DCT） | FDConv, vHeat, TOST |
| `mamba/` | SSM状态空间模型 | EfficientViM, WTE_Mamba |
| `dynamic/` | 动态/自适应卷积 | DynamicConv |
| `context/` | 全局上下文聚合 | EVC, ContextAgg |
| `neck/` | 颈部模块（上采样/融合） | CARAFE, ASF |
| `loss/` | 独立损失/后处理工具 | NWDLoss, SoftNMS |

**2b. 创建模块文件**: 文件名 = 模块名.py

**2c. 类定义规则**:

```python
# ===== 单输入模块模板 (替换Conv/C3k2) =====
class YourModule(nn.Module):
    """模块名: 一句话描述

    机制: (2-3句核心原理)
    对RGBT的价值: (1句)
    用法: [-1, 1, YourModule, [c2, ...args]]

    参数:
        c1: 输入通道数 (由parse_model自动注入)
        c2: 输出通道数
        ...: 其他参数
    """
    def __init__(self, c1, c2, ...):  # 必须含 c1, c2
        super().__init__()
        # 1x1 通道对齐 (必须)
        self.proj = nn.Conv2d(c1, c2, 1) if c1 != c2 else nn.Identity()
        # 核心逻辑
        ...
    def forward(self, x):
        x = self.proj(x)
        ...
        return x

# ===== 多输入模块模板 (替换Concat, from为列表) =====
class YourFusion(nn.Module):
    """融合模块: 一句话描述

    用法: [[vis_layer, ir_layer], 1, YourFusion, [c2, ...args]]
    注意: from是列表时, c1会被parse_model自动转为list
    """
    def __init__(self, c1, c2, ...):
        super().__init__()
        if isinstance(c1, (list, tuple)):
            c_vis, c_ir = c1[0], c1[1]  # 分别取两个输入通道
        else:
            c_vis = c_ir = c1
        self.proj_vis = nn.Conv2d(c_vis, c2, 1) if c_vis != c2 else nn.Identity()
        self.proj_ir  = nn.Conv2d(c_ir, c2, 1)  if c_ir != c2  else nn.Identity()
        ...
    def forward(self, x):
        if isinstance(x, (list, tuple)):
            a, b = x[0], x[1]
        else:
            a = b = x
        a, b = self.proj_vis(a), self.proj_ir(b)
        ...
        return fused

# ===== 检测头模板 (替换Detect) =====
class YourHead(nn.Module):
    """检测头: 一句话描述
    用法: [[P3, P4, P5], 1, YourHead, [nc, hidc]]
    """
    # 必需的类属性 (YOLO框架要求)
    dynamic = False
    export = False
    format = None
    end2end = False
    max_det = 300
    shape = None
    anchors = torch.empty(0)
    strides = torch.empty(0)

    def __init__(self, nc=80, hidc=256, ch=()):
        super().__init__()
        self.nc = nc
        self.nl = len(ch)
        self.reg_max = 16
        self.no = nc + self.reg_max * 4
        self.stride = torch.zeros(self.nl)
        # 1x1投影对齐P3/P4/P5不同通道
        self.proj = nn.ModuleList([nn.Conv2d(c, hidc, 1, bias=False) for c in ch])
        ...
    def forward(self, x):
        x = [self.proj[i](x[i]) for i in range(self.nl)]
        # ... 检测逻辑
        # 训练路径返回 list; 推理路径返回 (y, x)
        if self.training: return x
        ...
        return y if self.export else (y, x)
    def bias_init(self):
        self.cv2.bias.data[:] = 1.0
        self.cv3.bias.data[:self.nc] = math.log(5 / self.nc / (640 / 16) ** 2)
    def decode_bboxes(self, bboxes):
        return dist2bbox(self.dfl(bboxes), self.anchors.unsqueeze(0), xywh=True, dim=1) * self.strides
```

**2d. 硬约束**:
- 禁止依赖 mmcv / mmengine / mamba-ssm（只能用 PyTorch + torchvision + timm）
- c1/c2 必须作为前两个位置参数
- 1x1 投影必须在 `__init__` 中处理 c1 != c2 的情况
- 文件名 = 主类名.py

**2e. 创建 `__init__.py`**: 如果子目录是新的，创建 `__init__.py`，内容为 `from .模块名 import *`

**4a. 核心原则**: **原位替换** — 不改层号，只换模块名。除非必须插入新层（此时需层号位移对照表）。

**4b. YAML 目录规则**:
```

分类: conv / dynamic / context / neck / head / frequency / mamba / fusion / attention
```

**4c. 创建流程**:

**常见训练报错及修复**:
- `Sizes of tensors must match` → 检查模块在空间1x1 (P5) + bs=1时是否兼容，BN改GroupNorm
- `Expected more than 1 value per channel` → BatchNorm在GAP后空间1x1时崩溃，改GroupNorm
- `register_buffer` 与 EMA 不兼容 → 改用普通 dict 缓存（参考 vHeat_Fusion）
- CUDA OOM → 减小 batch size 或 imgsz
- `module not found` → 检查 `__init__.py` 导入和 `tasks.py` 注册

## 十、项目全景理解（给下一个 Agent）

> 本节是对整个项目的深度理解，读完即可达到与前任 Agent 相同的工作水平。

### 10.1 项目定位

这是一个**基于 YOLO 框架的 RGB-T (可见光+红外) 双模态目标检测研究项目**。
核心目标: 在 YOLO 架构上系统性地集成、对比、筛选各种即插即用模块（注意力/卷积/融合/频域/SSM等），
找到最优的双模态检测配置，最终产出一篇高质量论文。

### 10.2 关键架构概念

**双模态 Mid-Fusion 架构**:
```
输入 [B,4,H,W] (RGB 3ch + IR 1ch)
    |
    ├─ SilenceChannel [0,3] → RGB分支 (独立backbone)
    └─ SilenceChannel [3,4] → IR分支 (独立backbone)
         |
    P3: Concat [vis_P3, ir_P3] → 融合模块 → Neck
    P4: Concat [vis_P4, ir_P4] → 融合模块 → Neck
    P5: Concat [vis_P5, ir_P5] → 融合模块 → Neck
         |
    SPPF → C2PSA → FPN/PAN Neck → Detect
```

**层号体系**: backbone 共 21 层 (层0-20) + 3个融合层 (层21/22/23) + SPPF(24) + C2PSA(25)，
然后 head 从层26开始。替换融合层时**原位替换**，不改变层号。

**模块分类与放置规则**:
- `fusion/`: 双输入融合模块 (from为列表) — CIFusion, AFF, vHeat_Fusion, FCMMFusion 等
- `attention/`: 单输入注意力 (from为单层) — CBAM, ECA, CoordAtt 等，插在 Concat 之后
- `conv/`: 卷积变体 — 替换 Conv 或 C3k2
- `frequency/`: 频域模块 — FDConv, vHeat, TOST 等
- `head/`: 检测头 — 替换 Detect
- `neck/`: 颈部模块 — CARAFE, ASF 等
- `mamba/`: SSM 模块
- `dynamic/`: 动态卷积
- `context/`: 全局上下文
- `loss/`: 独立损失工具

### 10.3 模块接入的三个关键文件

**文件1: `ultralytics/nn/ExtraModules/__init__.py`**
作用: 模块的导入入口。所有新模块必须在这里 `from .子目录.模块名 import *`，
且必须放在 `# YOLO 包装器` 行之前。

**文件2: `ultralytics/nn/tasks.py`**
作用: 模块注册。有三个注册点:
- `base_modules` (约1080行): 所有模块都要加
- `parse_model` 多输入分支 (约1183行): 仅融合模块 (from为列表) 需要加
- `repeat_modules` (约1140行): 仅需要 n 参数的模块需要加

**文件3: YAML 配置文件**
作用: 定义模型结构。放在 `ultralytics/cfg/models/26-RGBT/{YYYY-MM-DD}/{分类}/` 下，
从基线 `ultralytics/cfg/models/26-RGBT/origin/yolo26-RGBT-midfusion.yaml` 复制后修改。

### 10.4 常见踩坑点

1. **BatchNorm + 空间1x1 + bs=1 崩溃**: YOLO 初始化时用 `torch.zeros(1, ch, 32, 32)` 做 stride 推断，
   P5 层空间为 1x1，BatchNorm2d 会报 "Expected more than 1 value per channel"。
   **解决方案**: 所有门控/归一化路径统一用 `nn.GroupNorm(1, channels)` 替代 `nn.BatchNorm2d`。

2. **EMA 不兼容 register_buffer**: EMA 保存模型状态字典时，register_buffer 的动态缓存会导致 key 不匹配。
   **解决方案**: 用普通 Python dict 缓存（参考 vHeat_Fusion 的 `_dct_cache`）。

3. **timm 版本兼容**: `timm.models.layers` 已废弃，应改用 `timm.layers`。
   当前代码中有 FutureWarning，不影响功能但需注意。

4. **YAML 层号引用**: neck 的 Concat 引用的是 backbone 层号，替换融合层后如果层号变了，
   必须同步更新所有引用。推荐原位替换避免此问题。

5. **c1 参数传递**: 多输入模块的 c1 会被 parse_model 自动转为 list `[ch[f] for x in f]`，
   所以 `__init__` 必须处理 `isinstance(c1, (list, tuple))` 的情况。

4. **行内代码**: 文件路径、模块名、参数用反引号包裹
5. **代码块**: 命令行示例用 ` ```bash ` 包裹
6. **中文为主**: 技术术语保留英文，描述用中文

### 11.5 指令.md 编写规范

指令.md 是**操作手册**，不是实验记录。编写原则:
1. **模块参数速查表**: 每次新增模块后，必须在"四、模块参数速查表"对应分类下追加一行
2. **模块清单**: 更新"七、现有模块完整清单"中的计数和列表
3. **外部来源**: 更新"六、外部模块来源"中的列表
4. **tasks.py 插入模板**: 如有新的注册模式（如新的多输入模块类型），更新"五、tasks.py 精确插入模板"
5. **不追加实验记录**: 实验记录写在创新点.md 和改进位置.md，不写在指令.md
6. **保持可操作性**: 每一条信息都应该是"可直接执行"的，不要写泛泛的描述

### 11.6 文档间分工

| 文档 | 记录什么 | 谁读 |
