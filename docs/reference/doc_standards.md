# Markdown 文档编写规范

> 本文件从 `指令.md` 拆分，规定 `docs/` 下各文档的编写格式。
> 更新文档（步骤 6）时查阅。

---

## 一、通用规则

1. **日期标题**: 不同日改进加 `## YYYY-MM-DD`，同日多次改进不重复加日期头
2. **追加原则**: 所有内容追加到文档末尾，不修改已有内容
3. **表格优先**: 结构化信息用 Markdown 表格，不用纯文本列表
4. **行内代码**: 文件路径、模块名、参数用反引号包裹
5. **代码块**: 命令行示例用 ` ```bash ` 包裹
6. **中文为主**: 技术术语保留英文，描述用中文

---

## 二、改进位置.md 编写规范

每次追加必须包含以下结构:

```markdown
## YYYY-MM-DD

### 新增 XXX 模块 (简要描述)

> 配置目录: `ultralytics/cfg/models/26-RGBT/YYYY-MM-DD/分类/`
> 来源: 来源仓库/论文

**筛选分析** (仅当涉及外部源码筛选时):
| 模块 | 决定 | 原因 |

**文件修改对照表**:
| 配置/代码 | 改动 |

**代码文件修改表**:
| 文件 | 行号 | 改动 |

**XXX 模型参数**:
- YOLO26s-midfusion-XXX: N layers, M params, F GFLOPs
- vs 基线: +X params, +Y GFLOPs

**层号位移对照** (仅当有位移时，分 Backbone 和 Head 两张表)

**架构示意** (仅当模块改变数据流时，用 ASCII 图)
```

## 三、创新点.md 编写规范

每次追加必须包含以下结构:

```markdown
## YYYY-MM-DD

### 新增 XXX 模块 (简要描述)

> 来源: 论文名 / 仓库名

| 模块 | 来源 | 核心机制 | 参数量 |

**核心创新**: 2-4 条要点，说明与已有模块的区别

**插入策略**: 替换/插入哪个层、为什么选这个位置

**验证结果**: 导入/forward/YAML/训练 哪些通过
```

## 四、论文级创新点.md 编写规范

仅当模块满足以下准入条件之一时才更新:
- mAP50 > 0.865（经训练验证）
- 创新性极高，提点潜力巨大（机制原创性足以独立成文）

每个条目必须标注涉及模块的 mAP50 实测值。仅当 mAP50 > 0.865 时才画架构设计图（ASCII 架构图，参考 vHeat_Fusion 条目风格）。结构:

```markdown
## YYYY-MM-DD

### XXX: 简要描述

> **创新等级**: ⭐~⭐⭐⭐
> **来源**: 论文/仓库
> **mAP50**: 实测值（或"待训练"）

#### 一、问题定义
(RGB-T 检测中这个模块解决什么具体问题)

#### 二、核心创新机制
(详细的技术描述，含公式/伪代码/流程图)

#### 二.五、架构设计 ← 仅 mAP50 > 0.865 时才写此节
(ASCII 架构图，参考 vHeat_Fusion 条目风格)

#### 三、与现有方法对比
(表格对比参数量、复杂度、融合域等)

#### 四、消融实验建议
(列出 3-5 个可做的消融实验)

#### 五、实现验证
(表格列出模块文件、YAML、参数量、测试结果)
```

## 五、指令.md 编写规范

指令.md 是**操作手册**，不是实验记录。编写原则:
1. **模块参数速查表**: 每次新增模块后，必须在 [模块参数速查表](module_args.md) 对应分类下追加一行
2. **模块清单**: 更新"七、现有模块完整清单"中的计数和列表
3. **外部来源**: 更新"六、外部模块来源"中的列表
4. **tasks.py 插入模板**: 如有新的注册模式（如新的多输入模块类型），更新 [代码模板](code_templates.md)
5. **不追加实验记录**: 实验记录写在创新点.md 和改进位置.md，不写在指令.md
6. **保持可操作性**: 每一条信息都应该是"可直接执行"的，不要写泛泛的描述

## 六、文档间分工

| 文档 | 记录什么 | 谁读 |
|------|----------|------|
| **指令.md** | 操作手册 + 项目理解 + Agent指南 | 下一个接手的 Agent |
| **常见错误与修复.md** | 已知 runtime 错误的根因、修复模式、自检清单 | 集成新模块/创建 YAML 时的 Agent |
| **改进位置.md** | 每次改进的具体代码改动、层号位移、文件修改表 | 需要回溯改动的 Agent/人类 |
| **创新点.md** | 所有模块改进的创新点说明 | 写论文时查阅 |
| **论文级创新点.md** | 仅原创设计的深度分析 | 论文核心贡献章节 |
